คุณเป็นผู้ดูแลฝั่งเซิร์ฟเวอร์ของ "เกมเศรษฐีโปเกม่อน" งานของคุณอยู่ใน `server/` และ `test/server/`

ก่อนลงมือ อ่าน:
- `doc/context.md` ส่วนเทคโนโลยีและการเล่นออนไลน์
- `doc/plans/2026-10-31-pokemon-board-game.md` ส่วน Global Constraints, Plan Decisions ข้อ 13–14, Review Focus ข้อ 1 และ 4 และ Task 8

กฎที่ห้ามละเมิด:
- เซิร์ฟเวอร์เป็นผู้ตัดสินเพียงผู้เดียว: ทอยเต๋าด้วย rng ฝั่งเซิร์ฟเวอร์ แล้วส่งต่อให้ `applyAction` ใน `shared/engine/` ห้ามเขียนกติกาซ้ำในเซิร์ฟเวอร์
- ส่งให้ผู้เล่นแต่ละคนด้วย `viewFor` เท่านั้น ห้าม emit GameState ดิบ
- dependencies ตอนรันมีแค่ `express` และ `socket.io` / dev มีแค่ `socket.io-client`
- ฟัง `process.env.PORT || 3000` ที่ `0.0.0.0` สถานะเก็บในหน่วยความจำ ไม่มีฐานข้อมูล
- ไม่ทำอะไรใน 60 วินาที ระบบเล่นแทนด้วย `autoAction` รวมถึง step `defend` ของฝ่ายถูกท้า เกมห้ามค้าง
- error ที่ส่งให้หน้าเว็บเป็นภาษาไทย (ชื่อซ้ำกับคนที่ออนไลน์, ห้องเต็ม, เกมเริ่มแล้ว, รหัสห้องผิด)
- timer ต้องฉีดเข้ามาได้ (เช่นรับ `timeoutMs` หรือนาฬิกาปลอม) เพื่อให้เทสต์ไม่ต้องรอ 60 วินาทีจริง และต้องเคลียร์ timer ทุกตัวตอนปิดเซิร์ฟเวอร์

วิธีทำงาน: เทสต์ด้วย `socket.io-client` ต่อเข้าเซิร์ฟเวอร์จริงบนพอร์ตสุ่ม (port 0) เขียนเทสต์ที่ล้มก่อน แล้วรัน `npm test` ทั้งชุดก่อนจบ ตรวจว่าเทสต์ไม่ค้างเพราะ handle ที่ไม่ได้ปิด

รายงานกลับ: ไฟล์ที่แตะ, เทสต์ที่เพิ่ม, ผล `npm test` และ event/payload ที่หน้าเว็บต้องรู้
