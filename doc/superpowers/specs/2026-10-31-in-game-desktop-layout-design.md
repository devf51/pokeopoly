# ปรับหน้าในเกมบนคอม: ย้ายปุ่มคำสั่งไปกลางกระดาน

ขนาดงาน: เปลี่ยนเล็ก–กลาง (หน้าเว็บอย่างเดียว ไม่แตะกติกาและเซิร์ฟเวอร์)

## ทำไม

ผู้เล่นบอกว่าหน้าในเกม "ใช้งานยาก เข้าถึงฟังก์ชันยาก บางครั้งต้องเลื่อนลง" เมื่อเล่นบนคอม
สาเหตุในโค้ดตอนนี้:
- แผงขวาสูงได้เท่าจอ (`.panel { max-height: calc(100dvh - 2rem); overflow-y: auto }`) ของที่ล้นต้องเลื่อนในแผง
- การ์ดปุ่มคำสั่งเป็นอันดับ 3 ในแผง และบาง step ยาว (จับ: รูป + เลือกบอล + ติ๊กความสามารถ + ปุ่ม; รักษา/ขาย: รายการโปเกม่อน) ปุ่มยืนยันจึงหลุดลงล่าง
- ระหว่างตา สายตาอยู่ที่ลูกเต๋ากลางกระดาน แต่ปุ่มอยู่แผงขวา ต้องย้ายสายตาไปมา

## เป้าหมาย

- บนคอม (กว้าง ≥ 768px) ปุ่มคำสั่งของตาเราอยู่กลางกระดาน ใต้ลูกเต๋า
- ปุ่มยืนยัน/ปุ่มหลักของ step มองเห็นได้เสมอโดยไม่ต้องเลื่อนหน้าหรือเลื่อนแผง ที่จอ 1366×768 ขึ้นไป
- แผงขวาเหลือแค่ข้อมูล เรียงข้อมูลของเราขึ้นก่อน

## ไม่ทำ (non-goals)

- มือถือ (< 768px) คงเดิม: แผงและปุ่มอยู่ใต้กระดานเหมือนตอนนี้
- ไม่เปลี่ยนชุดปุ่ม ข้อความ หรือตรรกะใน `action-model.js` (เทสต์ `test/public/action-model.test.js` ต้องผ่านเหมือนเดิม)
- ไม่เปลี่ยนสี ฟอนต์ หรือหน้าตาของช่องบนกระดาน
- หน้าผลการแข่งตอนจบเกมคงอยู่ในแผงขวาเหมือนเดิม

## ถือว่าล้มเหลว แม้จะใช้ได้ (anti-goals)

- การ์ดคำสั่งบังลูกเต๋าหรือข้อความผลลัพธ์ระหว่างแอนิเมชัน
- กระดานถูกย่อเล็กลงจนดูช่องไม่ออก
- ปุ่มที่ตรึงไว้บังปุ่มอื่นหรือบังกรอบโฟกัสตอนกด Tab
- หน้ามือถือพัง

## แนวทางที่พิจารณา

| แบบ | สาระ | ได้ | เสีย |
|---|---|---|---|
| **ก. ปุ่มกลางกระดาน (เลือก)** | ย้ายการ์ดคำสั่งไปไว้ในพื้นที่กลางกระดาน 7×7 ใต้ลูกเต๋า | ปุ่มอยู่ตรงที่สายตามองอยู่แล้ว ไม่ต้องเลื่อน | ต้องจัดพื้นที่กลางกระดานใหม่ จอ 1366×768 มีที่ราว 540px |
| ข. ตรึงปุ่มบนสุดของแผงขวา | การ์ดตาของใคร + ปุ่มอยู่กับที่ ที่เหลือเลื่อน | แก้น้อย แทบเป็น CSS | ยังต้องสลับสายตา การ์ดสูงแล้วที่ข้อมูลเหลือน้อย |
| ค. 3 คอลัมน์ | ผู้เล่นซ้าย กระดานกลาง ปุ่มขวา | เห็นทุกอย่างพร้อมกัน | จอ 1366 คอลัมน์ข้างเหลือ ~300px แคบเกิน (ตัดทิ้ง) |

ผู้เล่นเลือกแบบ ก เพราะปัญหาหลักคือหาปุ่มยาก แบบ ก เอาปุ่มไปไว้ที่มองอยู่แล้ว

## สิ่งที่ตกลงกันแล้ว

- แบบ ก ใช้กับจอ ≥ 768px เท่านั้น

## สิ่งที่ผมตัดสินใจเอง (ตรวจได้)

- **กลางกระดานแบ่งเป็น 2 ส่วน:** บน = ลูกเต๋า + ข้อความ (`.stage`) ล่าง = การ์ดคำสั่ง เมื่อมีการ์ดคำสั่ง ส่วนลูกเต๋าย่อขนาดลงให้ยังเห็นตัวเลขชัด เมื่อไม่ใช่ตาเรา ไม่แสดงการ์ดรอ (`wait-card`) ในกลางกระดาน เพราะข้อความ "ตาของ X" ใน stage บอกอยู่แล้ว
- **ตอนแอนิเมชันเล่นอยู่** (ทอย เดิน จับ สู้) ซ่อนการ์ดคำสั่งไว้ก่อน แล้วค่อยแสดงหลังวาดสถานะใหม่ (`applyState`) เพื่อไม่ให้บังลูกเต๋า
- **การ์ดคำสั่งเป็น flex column สูงไม่เกินพื้นที่ที่เหลือในกลางกระดาน:** ส่วนตัวเลือก (รายการโปเกม่อน ชิปบอล) เลื่อนได้ภายในการ์ด แถวปุ่มหลักอยู่ล่างสุดของการ์ดเสมอ (ไม่เลื่อนหายไป) ใส่ `scroll-padding-bottom` เท่าความสูงแถวปุ่ม กันโฟกัสถูกบัง
- **ใช้ element `action-area` อันเดียว** ย้ายไปมาระหว่างกลางกระดาน (คอม) กับแผง (มือถือ) ด้วย `matchMedia('(min-width: 768px)')` ไม่วาดสองชุด เพื่อไม่ให้สถานะที่เลือกค้าง (`states` ใน `actions.js`) แยกกัน
- **ลำดับแผงขวาใหม่ (คอม):** การ์ดตาของใคร + เวลา → สรุปของเรา (เงิน บอล ความสามารถ) → โปเกม่อนของคุณ → ผู้เล่นคนอื่น → ประวัติ → คำอธิบายสีช่อง; แผงยังเลื่อนได้ แต่ไม่มีอะไรที่ต้องกดอยู่ในนั้น (ยกเว้นผลการแข่งตอนจบ)
- **ไม่เปลี่ยนขนาดกระดาน:** ยังคง `width: min(100%, calc(100dvh - 2rem))`

## เหลือให้คนเขียนโค้ดตัดสิน

- ขนาดตัวอักษร/ระยะในการ์ดคำสั่งตอนอยู่กลางกระดาน (ใช้หน่วย `cqw` ตามกระดาน หรือ rem) ขอแค่อ่านง่ายที่ 1366×768
- จะแยก "สรุปของเรา" เป็นการ์ดใหม่ หรือดึงการ์ดผู้เล่นของเราขึ้นไปอันแรก

## ตรวจว่าเสร็จ

- `npm test` ผ่านทั้งหมด
- เปิดห้อง 2 คนในเบราว์เซอร์ ที่ 1366×768 และ 1920×1080 เล่นผ่าน step: ทอยเดิน, จับ (เลือกบอล + ติ๊กความสามารถ), ร้าน (เลือกจำนวน), รักษา/ขายเมื่อมีโปเกม่อนหลายตัว, ท้าสู้/ถูกท้า — ปุ่มหลักอยู่ในจอทุกครั้งโดยไม่เลื่อน และไม่บังลูกเต๋า
- ที่ 375px หน้าตาเหมือนก่อนแก้
